Privacy Policy

How the internal reporting tool handles Google data.

Effective date: October 17, 2026

1. Operator and scope

Pelican Canvas operates Pelican Website Analytics to collect and analyze reports for its own website, pelican-canvas.com. This policy applies to that internal reporting application and the Google data it handles.

Contact: contact@pelican-canvas.com.

2. Data accessed and collected

After the owner grants Google authorization, the application reads:

  • Google Analytics 4 reports: dates, user and session counts, engagement, page views, source/medium, landing page paths and query strings, event names and counts, key events, and reported revenue.
  • Google Search Console reports: accessible site properties and permission levels; dates, search query text, page URLs, clicks, impressions, click-through rate and average position.
  • Operational records: sync timestamps, requested date ranges, source status, row counts and error messages. Error details can contain website or project identifiers.

These are reporting data returned by Google. Query text and page URLs can contain information entered into searches or URLs, so access to exported reports should be limited appropriately.

3. Purpose and permissions

Data is used to maintain website performance history, assess traffic and search visibility, troubleshoot imports, and support Pelican Canvas's business reporting and website improvements.

The Google consent screen requests read-only Analytics and Search Console access, spreadsheet read/write access, external API requests, and management of Apps Script triggers. Spreadsheet authorization can cover the owner's spreadsheets; the collector's configured output is one designated reporting spreadsheet. Source Analytics and Search Console settings are not modified.

4. Storage and protection

The collector runs in Google Apps Script. Report rows and sync logs are stored in a Google Sheet; import status and configuration are stored in Apps Script. Execution diagnostics may also appear in Google-managed Apps Script or Cloud logs.

Google handles account sign-in and authorization. The collector uses Google-managed authorization and a temporary access token for API requests. It does not write access tokens to report cells or application source files.

Access to the script and spreadsheet is controlled through Google permissions. The owner is responsible for granting access only to authorized people and protecting the Google accounts used.

5. Sharing and Limited Use

Google processes and hosts data through the Google services used by the application. Report access is available to the owner and authorized collaborators according to the spreadsheet and script permissions. Exporting or sharing reports through other tools is a separate action controlled by the owner.

The collector does not publish report data on these public information pages, sell Google user data, or send it to advertising services. Google data is used for the reporting purposes described above.

Pelican Website Analytics's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

6. Retention and deletion

Imported history and spreadsheet sync logs remain until the owner deletes them; the collector has no automatic expiry for those rows. Google-managed diagnostic logs follow the retention settings of the relevant Google service.

The owner can stop collection by removing the script's scheduled trigger or revoking the application's access in Google Account connections. Revoking access stops future authorized requests but does not erase previously exported reports.

To remove stored application reports, delete the dedicated Website report tabs, related Website settings and script properties, and relevant logs where Google provides deletion controls. Contact contact@pelican-canvas.com for access or deletion requests. Other existing business records in the reporting spreadsheet are outside this application's report tabs.

7. Changes to this policy

Updates will be published on this page with a revised effective date when the application's data practices change.
